# 새소망 방문요양센터

새소망 방문요양센터의 Next.js App Router 홈페이지입니다. V1·V2와 새소망 V3 시안을 로컬에서 비교할 수 있습니다.

## 필요 환경

- Node.js `>=22.13.0`

## 로컬 실행

```bash
npm install
npm run dev
```

개발 서버를 연 뒤 다음 경로를 확인합니다.

- `/` — 현재 V1 홈페이지
- `/v2` — Calm Navigator V2 시안
- `/compare` — V1/V2, Desktop/Mobile 비교 화면

## V3 1차 검토

- `/v3-design` — 1차 중립 prototype 검토 경로입니다. 11개 화면 블록과 placeholder 이미지 슬롯의 구조·동작을 확인합니다.
- 현재 문구와 이미지는 실제 서비스·사진·브랜드 확정 전의 중립 placeholder이며, 운영 정보로 해석하거나 게시용으로 사용하지 않습니다.
- 1차 기준은 구조와 상호작용을 고정합니다. 실제 문구, 사진, 브랜드 결정과 `/v3` 공개 경로는 2차 작업에서 분리해 반영합니다.

## V3 2차 로컬 프로토타입

- `/v3` — 새소망 문구, 전용 자산, 센터 소식, FAQ, 카카오 오픈채팅 상담 안내, 오시는 길을 연결한 로컬 검토 경로입니다. 별도의 상담 양식을 전송하거나 저장하는 기능은 이 경로의 현재 동작에 포함하지 않습니다.
- `/compare` — 기본 V1/V2 나란히 비교를 유지하며, `V3만` 선택으로 2차 프로토타입을 바로 확인할 수 있습니다.
- 기존 `/`, `/v2`, `/v3-design`, `/compare` 경로는 각 검토 목적에 따라 유지합니다.

### V3 자산과 로컬 리소스

- `/v3` 본문은 사진 표시 위치 12개를 유지합니다. Hero는 승인된 가로·세로 가상 실사 사진 중 화면 폭에 맞는 한 장을 선택하고, 나머지 가상 장면 11개(소개·안내 2개, 서비스 카드 3개, 돌봄 약속 1개, 상담 안내 4개, 브랜드 장면 1개)는 유지합니다. 상담 안내는 선택한 사진을 한 번에 하나씩 보여 줍니다. 이전 Hero·블로그 사진과 SVG 도해 9개는 이전 구성 재현용으로 보관하며 현재 화면에서는 불러오지 않습니다. 사진의 출처·권한 근거·SHA-256·crop·실제 차원은 `public/v3/saesomang/assets-manifest.json`에서 확인합니다.
- 상단 메뉴는 화면 전체 폭을 유지하고 본문은 최대 1440px, 주요 내부 내용은 최대 1200px로 중앙 정렬합니다. Hero 사진의 진입 확대는 없으며, 새 사진은 구간별 표시 폭을 제한하고 원본 비율을 유지합니다. 서비스 카드는 마우스를 올리면 덮개가 열리고, 키보드·터치로도 열고 닫을 수 있습니다. JavaScript가 없으면 설명을 기본 표시합니다.
- 소개·안내의 스크롤 전환, 돌봄 약속의 사진 등장, 상담 안내의 4탭·자동 전환·재생/정지, 하단 브랜드 장면과 정보 구간의 배경 연결을 유지합니다. 본문 상담 영역은 단일 카카오 버튼과 그룹방 안내로 구성하며 `#contact-cta`와 `#consult`가 같은 위치로 연결됩니다.
- 브랜드는 사용자가 승인한 ‘집 안의 새싹’ 심볼과 MaruBuri 글자형 조합입니다. 헤더·메뉴·대형·푸터의 5변형과 심볼 3종을 `public/v3/saesomang/brand/`에 보관합니다.
- 새소망 전용 폰트는 `/v3/saesomang/fonts/`의 로컬 subset을 preload하고 `styles/v3/saesomang-fonts.css`에서 사용합니다. 외부 폰트 요청에 의존하지 않습니다.
- 현재 Hero는 `picture`로 660px 이하에서 `hero-home-portrait.webp`, 그 밖에서 `hero-home-landscape.webp`를 선택합니다. JavaScript 실행 전에도 한 장만 요청하며 고유 파일명과 사전 압축한 WebP를 사용합니다. 원본 1619×971 / 971×1619는 확대하지 않았으며, 데스크톱 최대폭의 2배 픽셀 밀도 선명도를 충족한다고 주장하지 않습니다. 그 밖의 Next Image는 쿼리가 없는 로컬 경로와 새소망 WebP의 정확한 `?v=wu18-20261015` 쿼리를 계속 허용합니다. 같은 파일명을 교체할 때는 캐시 구분 방식과 `next.config.ts`의 `images.localPatterns`를 함께 확인합니다.

자산 생성기는 다음 명령으로 재현할 수 있습니다. 이 명령은 `scripts/build-v3-saesomang-assets.mjs`의 현재 입력과 출력 계약을 사용합니다.

```bash
node scripts/build-v3-saesomang-assets.mjs --evidence ../docs/enhancement/2026-10-15/evidence/wu18/pipeline
node --test --test-concurrency=1 tests/v3-assets.test.mjs
```

사진 생성기 실행에는 위 명령의 입력 원본과 기존 의존성이 필요합니다. 브랜드 생성기는 `python scripts/build-v3-saesomang-brand.py`이며 Python의 FontTools·Brotli와 저장소의 원본 폰트를 사용합니다. 브랜드를 다시 생성한 뒤 사진 생성기를 실행하면 OG 공유 이미지와 manifest도 함께 갱신됩니다. 문구 변경 시에는 `scripts/build-v3-saesomang-fonts.py`의 입력을 확인하고 새소망 폰트 서브셋을 다시 생성·검증합니다.

프로덕션 빌드와 로컬 실행은 다음과 같습니다.

```bash
npm run build
npm run start
```

### 승인된 히어로 가로·세로 사진 실제 적용

2026-10-19, 검토한 가로·세로 가상 실사 사진을 `/v3`에 적용했습니다. Hero 크기·문구·그라데이션·등장/스크롤/역스크롤 모션과 나머지 완료 구간은 유지했습니다. 660px 이하에서는 세로 사진, 그 밖에서는 가로 사진을 처음부터 한 장만 선택합니다. JavaScript 비활성 상태에서도 사진 선택이 동작하며, 가로는 오른쪽·세로는 중앙 기준 구도입니다. PNG 원본과 WebP는 승인 후보와 같은 바이트로 편입했습니다.

코드 검사·production build·전체 테스트43개와 브라우저123개 항목을 통과했습니다. 7개 화면 폭의 히어로 위치·문구·스타일·하단 구간 좌표/내용/이미지, 카드 열림·Escape·메뉴·정방향/역방향 스크롤·동적 움직임 감소·창 크기 변경·단일 사진 전송을 확인했습니다. 승인 미리보기7폭과 하단14개 캡처를 비교했으며, `/v3-design`은390/1440/2560px 전체 화면 픽셀 차이가0입니다. 마지막 로딩 우선순위 조정 후 재빌드·Hero 핵심 테스트3개·모바일/데스크톱 시작 화면과 단일 전송을 다시 확인했습니다.

같은 Lighthouse13.5.0 느린 모바일 조건으로 변경 전후 각3회 측정했습니다. LCP(주요 콘텐츠 표시 시간) 중앙값은 **3.9205초 → 4.433초(+0.5125초)**로 증가했고, 최종 성능 점수 중앙값79·접근성100·CLS(초기 화면 배치 이동)0입니다. 강제 `high` 이미지 우선순위 대신 `auto`를 사용했지만 증가를 해소하지 못했습니다. 기존 응답 약40KB 대비 새 세로 사진 약122KB라는 차이가 있으며, 증가 원인을 전송량 하나로 확정하지 않습니다. 목표2.5초를 달성하지 못했고 이번 측정값에 대한 별도 사용자 성능 예외 승인을 받은 것으로 기록하지 않습니다. 요청한 사진 품질과 모션을 보존한 구현 결과에 성능 경고를 함께 남깁니다.

기존 모바일 안내 팝업의 설명문 겹침과 `/v3-design`의 브라우저 기본 `favicon.ico` 404는 변경 전에도 확인되어 유지했습니다. 신규 앱 실행 오류·실패한 사진 응답은 없었습니다. 높은 픽셀 밀도 화면의 사진 해상도 한계, 실물 기기·다른 브라우저 엔진·공개 서버 미검증을 구분합니다. 상세 캡처·전후 측정·자체 검토는 Git 밖 로컬 `../docs/enhancement/2026-10-19/hero-implementation/result.md`와 `evidence/hero-implementation/`에 보관합니다.

## Vercel Git 배포 참고

Vercel에서 이 저장소를 Import하면 Next.js를 자동 감지합니다. 별도의 `vercel.json`이나 Output Directory 설정은 필요하지 않습니다.

- Root Directory: 저장소의 `site` 폴더를 선택한 경우 그 경로, 저장소 루트가 곧 `site`인 경우 기본값
- Build Command: 기본값 `next build`
- Output Directory: 설정하지 않음

배포 전에는 Vercel 프로젝트의 Root Directory가 `package.json`이 있는 폴더를 가리키는지만 확인하세요. Git push는 저장소 이력을 원격에 반영하는 작업이고, 배포는 Vercel 등의 환경에서 빌드 결과를 공개하는 별도 작업입니다. 이 README의 설명은 배포 실행을 의미하지 않습니다.
